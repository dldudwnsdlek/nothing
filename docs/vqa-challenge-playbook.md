## 01. 이 대회가 실제로 요구하는 것

### VQA란
이미지 한 장 + 그 이미지에 대한 질문을 함께 넣으면 모델이 답을 내놓는 과제.
이미지 분류가 "이건 고양이다" 하나를 맞히는 것이라면, VQA는 같은 사진을 두고
"몇 개인가", "무슨 색인가", "왼쪽 것은 무엇인가"를 모두 물을 수 있다.

이 대회의 예시:
- 이미지: 바구니에 담긴 페트병
- 질문: "바구니 속에 든 재활용품은 어떤 소재인가요?"
- 선지: `a.캔  b.병  c.플라스틱  d.비닐`
- 정답: `c`

즉 **객관식(4지선다) VQA**이며, 제출은 `id, answer` 두 컬럼 CSV에 소문자 한 글자.

### 전략의 분기점 — 생성하지 말고 채점하라
객관식이므로 답을 자유 생성한 뒤 파싱할 필요가 없다.
a·b·c·d 각 선지의 **로그확률을 계산해 argmax**를 취하면 된다.
- 출력 형식이 깨질 일이 구조적으로 없다
- 확률값이 남아 TTA·앙상블에 그대로 쓸 수 있다
- 랜덤 하한이 25%이므로, 그보다 낮으면 무조건 파이프라인 버그

### 점수는 네 축
| 축 | 내용 | 함의 |
|---|---|---|
| 정확도 | 리더보드 실시간 순위, 시간대별 기프티콘 | 유일한 경쟁 항목 |
| 재현성 | "데이터셋에 대한 재현성" | 시드·버전 고정, 한 줄 실행 |
| 효율성·성능 | 모델 크기 / VRAM / 추론 시간 | **무한 앙상블은 감점 요인** |
| 디스커션·발표 | 인사이트 글, 질문 답변, 반별 발표 | 남이 잘해도 내 점수가 안 깎이는 유일한 항목 |

정확도 1%를 위해 20모델 앙상블을 만드는 것보다,
7B 한 장으로 깔끔히 재현되는 파이프라인 + 좋은 문서 + 디스커션 글 3편이 총점에서 앞설 가능성이 크다.

### 시작 전 확인할 규정 6가지
| 항목 | 답에 따라 달라지는 것 |
|---|---|
| 사전학습 가중치 허용? | 불가 시 scratch 학습 / 소형 인코더 조합으로 전환 |
| 상용 API(GPT·Gemini·Claude) 허용? | 보통 금지. 허용돼도 재현성·효율 점수에서 불리 |
| 외부 데이터 허용? | 공개 쓰레기 분류 데이터셋 증강 가부 |
| 하루 제출 횟수 | 적을수록 로컬 검증셋 신뢰도가 생명 |
| 테스트 이미지 사용 범위 | pseudo-labeling 가부 |
| 코드 제출 시점·형식 | Phase 0부터 리포지터리를 제출 형태로 유지 |

## 02. 진행 가이드라인 (Phase 0–5, 2주 기준)

각 단계 끝에 **제출 가능한 무언가**가 남도록 설계했다.

### Phase 0 — 파이프라인 관통 (첫날 2~3시간)
모델을 만들지 않는다. 데이터를 읽어 제출 CSV를 뱉고 리더보드에 점수가 찍히는 것까지만.
- 전부 `c`로 채운 더미 CSV 제출 → 25% 근처면 정상, 0%/에러면 형식 오류
- 리포지터리 뼈대: `data/ src/ configs/ notebooks/ README.md requirements.txt`

**완료 조건**: 더미 제출이 리더보드에 정상 반영

### Phase 1 — EDA와 검증셋 (1일)
로컬 검증셋의 품질이 남은 기간 전체의 실험 속도를 결정한다.
- EDA 체크리스트 수행 (03장)
- **이미지 단위** GroupKFold split
- **텍스트 전용 베이스라인** (이미지 없이 질문+선지만) 측정

**완료 조건**: 검증 점수와 리더보드 점수가 같은 방향으로 움직임을 1회 확인

### Phase 2 — 제로샷 VLM + 선지 스코어링 (1~2일)
학습 없이 사전학습 VLM 사용. 요즘 모델은 파인튜닝 없이도 상당히 잘 맞힌다.
- 3B급 하나, 7B급 하나 비교
- 자유 생성 → 선지 로그확률 스코어링으로 교체
- 선지 순열 TTA 적용
- 프롬프트 3~4종 비교 (한국어/영어, 지시 형식, CoT 유무)

**완료 조건**: 제로샷 최고 점수와 설정이 실험 로그에 기록됨

### Phase 3 — LoRA 파인튜닝 (2~4일)
Phase 2 점수를 못 넘기면 실패한 것. 같은 검증셋·같은 프롬프트로 비교할 것.
- QLoRA(4bit), rank 8~32, lr 1e-4~2e-4, 2~3 epoch, bf16
- 비전 인코더 동결, LLM쪽 attention/MLP projection에 어댑터
- 학습 타깃 = 정답 글자 토큰 하나의 교차엔트로피
- 학습/추론 프롬프트를 **같은 함수**로 생성 (최다 버그 지점)

**완료 조건**: 파인튜닝 > 제로샷이 검증셋에서 재현됨

### Phase 4 — 오류 분석 기반 개선 (2~3일)
랜덤 하이퍼파라미터 탐색 금지. 틀린 문제 100개를 눈으로 보고 유형별로 센다.
- 글자 읽기에서 틀림 → 해상도 상향 / OCR 주입
- 작은 물체에서 틀림 → 크롭 후 재입력
- 오답 패턴이 다른 2~3모델만 확률 평균 앙상블

**완료 조건**: "무엇을 왜 고쳤고 몇 % 올랐는지" 표 완성

### Phase 5 — 재현성·효율·문서·발표 (마지막 2일)
채점 항목 4개 중 3개가 여기서 결정된다. 모델을 더 만지지 말 것.
- 클린 환경에서 `bash train.sh && bash infer.sh` 검증
- 파라미터 수 · 최대 VRAM · 장당 추론 시간 측정 표
- 데이터 처리/모델 개발 문서, 발표 자료

**완료 조건**: 처음 보는 사람이 README만으로 재현 성공

## 03. 데이터를 먼저 의심하라

이 데이터셋은 "데이터 수집 미션으로 모은 이미지를 퀴즈로 가공"한 것 —
즉 **교육생 수백 명이 각자 휴대폰으로 찍은 사진**이다. 여기서 예측 가능한 문제가 따라온다.

### EDA 체크리스트
| 확인할 것 | 발견 시 대응 |
|---|---|
| 정답 글자 분포 | 편중 시 다수 클래스 예측이 25% 넘는 무료 하한선 |
| 정답 위치 편향 | 순열 TTA로 중화, 학습 시 선지 셔플 |
| 질문 유형 분류 | **모든 후속 판단의 축.** 100개만 손으로 분류해도 충분 |
| 이미지당 질문 수 | 행 단위가 아니라 이미지 단위 split |
| 중복·유사 이미지 | perceptual hash로 그룹화 후 같은 fold |
| 해상도·종횡비 분포 | 입력 픽셀 예산 결정 |
| 선지 개수 | 3개·5개가 섞이면 하드코딩 전부 붕괴 |
| train/test 출처 차이 | 검증셋이 리더보드를 못 따라가는 1순위 원인 |

### 반드시 만들 진단 베이스라인 — 언어 사전(prior)
이미지를 넣지 않고 질문+선지만으로 학습해본다.
"어떤 소재인가요? → 플라스틱"처럼 이미지 없이 맞는 문제가 얼마나 되는지 알려준다.
텍스트만으로 60%가 나온다면 남은 승부처는 "이미지를 봐야만 풀리는 40%"이고, 거기에 자원을 집중해야 한다.
**디스커션 글감으로도 최상급.**

### 검증셋 설계
- Group: 이미지 ID(또는 phash). 같은 사진이 train/valid에 갈라지면 점수가 뻥튀기
- Stratify: 정답 글자 + 질문 유형
- split 결과를 파일로 저장해 커밋 (매번 새로 쪼개면 실험 비교 무의미)
- 3천 건 미만 → 5-fold, 이상 → 홀드아웃

## 04. 전처리 — 상황별 선택표

전처리는 많이 할수록 좋은 게 아니다. **질문이 무엇을 묻느냐에 따라 같은 처리가 약도 독도 된다.**

### 이미지 전처리
| 우선 | 상황 | 처리 | 이유 |
|---|---|---|---|
| 필수 | 휴대폰 사진 | EXIF 회전 보정 `exif_transpose` | 무시하면 사진이 90° 누운 채 입력됨. 수집형 데이터 1순위 버그 |
| 필수 | PNG/흑백/CMYK 혼재 | `.convert("RGB")`, 손상 파일 허용 | 채널 수가 다르면 배치가 깨지거나 조용히 이상값 |
| 필수 | 해상도 제각각 | 224 억지 리사이즈 **금지**. 모델 프로세서의 동적 해상도 사용 | 재질 표기·인쇄 같은 작은 단서가 통째로 날아감 |
| 중요 | VRAM 부족 | `max_pixels`/타일 수 상한으로 픽셀 예산 조절 | 해상도는 정확도와 메모리를 동시에 지배하는 단일 최대 손잡이 |
| 중요 | 중복 촬영 | perceptual hash 그룹화 | 제거가 아니라 fold 배치가 목적 |
| 선택 | 물체가 작음 | 전체 + 크롭 2뷰 | 개수 세기·글자 읽기에 효과. 비용 2배 |
| 선택 | 라벨 글자가 결정적 | OCR 결과를 프롬프트에 주입 | "무색페트", "알루미늄 캔"을 읽으면 재질 문제는 사실상 끝 |
| 주의 | 정규화 | 프로세서에 맡기기 | 직접 `Normalize` 재적용 = 이중 정규화 사고 |

### 텍스트·선지 전처리
| 상황 | 처리 | 이유 |
|---|---|---|
| 한글이 깨짐 | `unicodedata.normalize("NFC", s)` | 맥에서 만든 파일은 자모 분리된 NFD. 겉보기엔 같은데 비교·토크나이징이 어긋남 |
| 선지가 한 문자열 | 정규식 파서 + 형식 변형 대응 | `a.` `a)` `A.` `①`이 섞일 수 있음. 파싱 실패 건수를 셀 것 |
| 선지 개수 가변 | 4로 하드코딩 금지 | 3지선다 하나에 인덱싱 전부 밀림 |
| 전각·중복 공백 | 공백 정규화 | 토큰 수 증가, 프롬프트 정렬 흐트러짐 |
| 학습/추론 프롬프트 | **같은 함수 하나**로 생성 | 파인튜닝이 제로샷보다 낮은 원인 대부분 |

### 증강 — 질문 유형이 허용 여부를 결정한다
| 증강 | 안전 | 금지 조건 | 메모 |
|---|---|---|---|
| 좌우 반전 | 재질·개수 문제만 있을 때 | **위치·글자 문제** | "왼쪽 것은?"의 정답이 뒤집히고 인쇄 글자가 거울상이 됨 |
| 색상 지터 | 재질·개수·위치 | **색 문제** | 갈색/녹색/무색 유리 구분이 색 그 자체. 밝기·대비만 약하게 |
| 랜덤 크롭 | 대상이 크게 찍힌 사진 | 개수 문제 주의 | 잘려 나가면 "몇 개인가"의 정답이 바뀜. scale 하한 0.8+ |
| 회전 ±10° | 대부분 | — | 휴대폰 사진의 자연스러운 기울기. 가장 무난 |
| 블러·노이즈 | 재질 문제 | 글자 문제 주의 | 작은 글자를 지우면 역효과 |
| **선지 순서 셔플** | **거의 항상** | — | 이 과제 고유의 최고 증강. 위치 편향 차단 + 데이터 사실상 4배 |
| 질문 패러프레이즈 | 여유 있을 때 | — | 사람 검수가 필요해 비용 대비 효율 낮음 |

### 스니펫 1 — 안전한 이미지 로더
```python
from PIL import Image, ImageOps, ImageFile
ImageFile.LOAD_TRUNCATED_IMAGES = True

def load_image(path):
    img = Image.open(path)
    img = ImageOps.exif_transpose(img)   # 휴대폰 사진 회전 보정
    return img.convert("RGB")            # CMYK / RGBA / 흑백 통일
```

### 스니펫 2 — 선지 파서 (NFC 정규화 포함)
```python
import re, unicodedata

PAT = re.compile(r"(?:^|\s)([a-dA-D])[.)]\s*")

def parse_choices(raw: str) -> dict:
    """'a.캔 b.병 c.플라스틱 d.비닐' -> {'a':'캔', 'b':'병', ...}"""
    s = unicodedata.normalize("NFC", raw).replace("　", " ").strip()
    parts = PAT.split(s)                 # ['', 'a', '캔 ', 'b', '병 ', ...]
    it = iter(parts[1:])
    return {k.lower(): v.strip() for k, v in zip(it, it)}

# 파싱 실패 건수를 반드시 셀 것 — 0이 아니면 정규식을 고칠 것
```

## 05. 모델 선택 — 어떤 경우에 무엇을

"제일 좋은 모델"은 없고 **내 GPU와 내 데이터 크기에서 제일 좋은 모델**만 있다.

### 세 가지(+1) 접근 계열
| 계열 | 작동 방식 | 강점 | 약점 | 이럴 때 |
|---|---|---|---|---|
| **A. 임베딩 유사도** (CLIP/SigLIP) | 이미지와 각 선지를 같은 공간에 임베딩, 코사인 유사도 최대 선택 | 초경량·초고속, 학습 거의 불필요, 효율성 점수 유리 | 추론형에 무력, 한국어 텍스트 인코더 약함 | GPU가 없다시피 하거나 질문이 단순 재질·물체 식별 위주. 앙상블 멤버로 훌륭 |
| **B. 생성형 VLM 제로샷** | VLM에 이미지+질문+선지 입력 후 선지 확률 계산 | 학습 0, 당일 점수 확보, 상식·추론·한국어 커버 | 추론 비용, 프롬프트 민감도, 위치 편향 | **거의 모든 경우의 첫 단계** |
| **C. VLM 파인튜닝** (LoRA/QLoRA) | B에 어댑터를 붙여 소량 학습 | 보통 최고 정확도, 도메인 어휘 흡수 | 과적합, 느린 실험 사이클 | 학습 데이터 2천 건 이상 + GPU 시간 확보 |
| **D. 고전 융합 모델** | 이미지 인코더 + 한국어 텍스트 인코더 특징 결합 → 4-way 분류 | 가볍고 통제 가능, 구조 설명이 명확해 발표 유리 | 사전지식 없어 상식형에 약함 | 대형 LLM이 규정상 제한되거나 질문이 정형 템플릿일 때 |

### GPU × 데이터 크기 결정 매트릭스

## 06. 기법 ROI 순위

투입 시간 대비 점수 상승이 큰 순서. **위에서부터 차례로** 할 것.

| # | 기법 | 비용 | 효과 | 설명 |
|---|---|---|---|---|
| 1 | 선지 로그확률 스코어링 | 몇 시간 | 중~대 | 파싱 제거. 형식 오류 실점이 0이 되고 확률값이 남음 |
| 2 | 선지 순열 TTA | 반나절 | 중 | 순서를 회전시켜 4번 예측, **내용 기준** 확률 평균 → 위치 편향 소멸 |
| 3 | 입력 해상도 상향 | 설정 한 줄 | 중~대 | 단일 하이퍼파라미터 중 영향 최대. 픽셀 예산 2배로 재측정 |
| 4 | 프롬프트 형식 실험 | 반나절 | 소~중 | 선지 제시 방식, 지시문 언어, "정답 글자만 출력" 강제. 3~4종이면 충분 |
| 5 | LoRA 파인튜닝 | 2~4일 | 대 | 데이터가 충분할 때 가장 확실. 단 1~4를 먼저 |
| 6 | OCR 텍스트 주입 | 1~2일 | 유형 의존 | 글자 문제 비중이 크면 대박, 없으면 헛수고. **오답 분석 후 결정** |
| 7 | 2~3모델 확률 앙상블 | 1일 | 소~중 | 오답 패턴이 다른 모델끼리만. 효율성 점수와 상충하니 절제 |
| 8 | Chain-of-Thought | 비쌈 | 양날 | 개수·추론형엔 도움, 단순 인식형엔 손해. **유형별로 켜고 끌 것** |

### 스니펫 3 — 선지 스코어링 + 순열 TTA
```python
import torch

@torch.no_grad()
def score_options(model, proc, image, question, choices):
    """각 선지의 로그우도를 재서 점수화. 파싱 실패가 구조적으로 없음."""
    prompt = build_prompt(question, choices)          # 학습/추론 공용 함수
    inputs = proc(images=image, text=prompt, return_tensors="pt").to(model.device)
    logits = model(**inputs).logits[0, -1]            # 다음 토큰 분포
    logp   = torch.log_softmax(logits.float(), dim=-1)
    return {k: logp[proc.tokenizer.encode(k)[-1]].item() for k in choices}

def circular_predict(model, proc, image, question, choices, rounds=4):
    """선지 순서를 회전시켜 위치 편향 제거 → 내용 기준으로 확률 평균"""
    keys = list(choices)
    agg  = {k: 0.0 for k in keys}
    for r in range(rounds):
        rot      = keys[r:] + keys[:r]
        remap    = {new: old for new, old in zip(keys, rot)}   # 새 위치 -> 원래 선지
        shuffled = {new: choices[remap[new]] for new in keys}
        for new, v in score_options(model, proc, image, question, shuffled).items():
            agg[remap[new]] += v / rounds
    return max(agg, key=agg.get), agg                  # agg는 앙상블에 재사용
```
실제 API는 모델 계열마다 다르므로 `build_prompt`와 토큰 인덱싱만 맞춰 바꾸면 된다.
구조 — *확률을 재고, 순서를 돌리고, 내용 기준으로 평균낸다* — 는 동일하다.

## 07. 자주 빠지는 함정

대부분 "모델이 나빠서"가 아니라 "파이프라인이 조용히 틀려서" 생기는 손실이다.

| 위험 | 증상 | 진짜 원인 | 대응 |
|---|---|---|---|
| 치명 | 리더보드가 25% 근처에서 안 움직임 | id 순서·개수 불일치, 대문자 `A` 제출, 인덱스 컬럼 포함 | 제출 직전 assert 검증 |
| 치명 | 검증 95%인데 리더보드 40% | 같은 이미지가 train·valid 양쪽에 존재 | 이미지 단위 GroupKFold |
| 치명 | 파인튜닝 < 제로샷 | 학습 프롬프트 ≠ 추론 프롬프트 | 프롬프트 생성 함수 통일 + 테스트 |
| 높음 | 특정 선지만 많이 고름 | 선지 위치 편향 | 순열 TTA + 학습 시 선지 셔플 |
| 높음 | 이미지를 가려도 점수 그대로 | 모델이 이미지를 무시하고 언어 사전만 사용 | 이미지 토큰 실제 입력 확인, 텍스트 전용 베이스라인과 비교 |
| 높음 | 이미지 절반이 누워 있음 | EXIF 회전 미적용 | `exif_transpose` 후 100장 육안 확인 |
| 중간 | 한글 매칭 실패 | NFC/NFD 혼재 | 모든 텍스트를 NFC로 정규화 |
| 중간 | 마감일에 코드가 안 돌아감 | 노트북에만 존재하는 파이프라인 | Phase 0부터 스크립트화, 매일 클린 실행 1회 |
| 낮음 | 매번 결과가 다름 | 시드 미고정, 비결정적 커널 | 시드 고정 + 추론 `do_sample=False` |

### 디스커션 글감 (가장 저평가된 점수)
1. **EDA 리포트** — 정답 분포, 질문 유형, 이미지 통계, 중복률. 초반에 올리면 가장 많이 읽힌다
2. **"이미지 없이 몇 %까지 맞출까"** — 텍스트 전용 베이스라인. 화제성·유용성 최상
3. **제출 형식 관통 가이드** — 첫날 사람들이 가장 많이 막히는 지점
4. **선지 순서를 바꾸면 정답률이 바뀐다** — 위치 편향 실험
5. **삽질 기록** — EXIF 회전, NFC/NFD 같은 실패담. 성공담보다 반응이 좋다
6. **제로샷 모델 비교표** — 같은 검증셋·같은 조건 측정

글은 **초반에 쓸수록 유리하다.** Phase 1이 끝나는 시점에 첫 글을 올릴 것.
공유 범위(코드 전체 공개 가부)는 대회 규정을 먼저 확인.

### 발표 구성 (10분 기준)
1. 문제 정의 — 객관식 VQA, 랜덤 25% (30초)
2. 데이터에서 발견한 것 — EDA 그래프 1~2장 (2분)
3. 가설과 실험 — "언어 사전이 강할 것이다 → 확인 → 그래서 X에 집중" (3분)
4. 결과 — 효율성 리포트 + 어블레이션 (2분)
5. 오답 분석 — 실제로 틀린 이미지 2장과 이유 (1.5분)
6. 한계와 다음 수 — 정직하게. 심사자가 가장 좋아하는 슬라이드 (1분)

정확도가 1등이 아니어도 발표는 1등을 할 수 있다.
"왜 이 선택을 했는가"가 명확하고 실패를 숨기지 않은 발표가 거의 항상 이긴다.
